# AutoColor — 白模自动分色

角色的数字涂装师：作者模型包（分件 STL + 渲染图）→ 自动吸色分色 → **多色 FDM 打印文件**（涂色 3MF，Bambu Studio / Orca / Snapmaker Orca 直接打开）。颜色不受色板数限制（连续 RGB 输出），耗材映射交给切片软件。

## 功能特性

- **世界坐标装配**：分件 STL 拖入即按世界坐标自动组合，无需手动对位
- **件级自动配色（一期，main）**：转台渲染图吸色 → 逐件配色；同前缀切件/左右对称件自动同色；件名语义匹配（hair/gem/boot/hood…）
- **面级自动涂装（R1-R2，开发分支）**：件内二次上色——多视角面级证据收集 → 边缘生长发现涂装区域 → 统一裁决 → per-face 涂色 3MF
- **连续 RGB 预览**：三视图（完整颜色/件级颜色/打印槽）、刷新自动恢复、人工 override 永远优先
- **卫生层与确定性**：过曝/欠曝/白框治理、截尾中位、跨视角裁决；两次运行结果逐位一致

## 快速开始

1. `run.bat` → http://127.0.0.1:8761/
2. 拖入全部分件 STL（保持世界坐标）
3. 上传 1~N 张渲染图（自动剔背景、多图色板合并）
4. 「自动按件配色」获得件级颜色
5. 转台取色（前端拟合全局姿态）→ 面级候选收集 → 摘要审查/override → apply
6. 导出涂色 3MF

要求：Python 3.10+，`pip install -r requirements.txt`（FastAPI / numpy / trimesh / PIL）；前端无构建，three.js 本地 vendor。

## 工作原理

两级管线：

- **R1 件级**：件 ID 缓冲几何可见性取色（先收集后决策，与视角顺序无关）+ 转台全局姿态拟合 + L0 卫生层（过曝钳制/欠曝剔除/白框带剔除）+ 截尾中位 + 亮视角优先 + 跨视角裁决与旗帜
- **R2 面级**：多视角面级证据收集（投影映射 + ID/深度门控 + 5×5 邻域截尾采样）→ ΔE 种子 + 焊接邻接 BFS 边缘生长（涂装跨折痕，法线约束全开）→ 统一裁决（置信度 ≥ 0.75 且独立视角 ≥ 2 才落色）→ base → accepted → override 三层合成

## 当前已知问题与困难

1. **区域色质量（主战场）**：转台渲染图为灯随相机的 headlight 布光，同一面的明暗状态在所有视角下恒定——跨视角一致性对"光影 vs 涂装"完全失灵。后果：光影梯度天然成为候选（测试模型 56 件/882 万面产生 1.4 万+ 候选区域，过分割），且区域代表色取跨视角中位后明暗混合、观感偏灰调
2. **打印映射链路未闭合**：Bambu per-face paint 硬上限 16 耗材槽，全自动接受流下区域色排在件色之后（paint_color=0）；需要"圈选区域 → 近色合并 → ≤16 槽"的人工圈选 UI，尚未实现
3. **Bambu Studio 实测未完成**：涂色 3MF 的 extruder/槽位显示需实测确认，实测通过前开发分支不并入 main
4. **收集性能**：全件面级证据收集 ~15 分钟（逐面加权中位未向量化，优化方案已知）
5. **3MF 体积**：涂色 3MF 为文本 XML，大模型导出可达数百 MB，切片器打开慢
6. **GPU 链路旁路**：SAM2 语义分割、Intrinsic 本征分解已调研有库存，尚未与现行管线整合

## 改进方向

1. **光照归一（针对问题 1 的已定方案）**：headlight 模型下亮度 ≈ f(法线·视线)，光影是几何可解释的而涂装不是——逐区域拟合 shading 归一反照率 + 种子判据色度域化（降 L 权）+ 区域代表色取亮观测 + 相邻近色合并；配套证据缓存落盘（收集一次、调参秒级迭代）
2. **打印映射 UI**：摘要圈选 → 近色合并 → ≤16 耗材槽 → face_slots 映射
3. **Bambu Studio 实测 → 分支合并**：解锁 main 吃到 R1-R2 全部能力
4. **收集向量化**：逐面加权中位改顺序统计，全件收集时长预期大幅下降
5. **渲染图点击取色**：人工 face override 的可视化入口（后端存储已就位）
6. **GPU 链路整合**：SAM2/Intrinsic 作为区域发现的语义先验与 shading 来源
